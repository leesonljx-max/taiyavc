# V1.6：列表服务端分页 + 行业图谱重设计（ECharts 树图 + 时间维度）

## 背景

慢的问题已定位（VPN 绕行），但排查中确认了两个架构隐患：
1. 所有列表接口（/api/projects、/api/project-leads、/api/ai-leads）都是"全量返回 + 前端 filter/slice 分页"，且前端的行业下拉、阶段统计卡片、AI 线索统计卡片都从全量数据派生。数据量增长后（AI cron 每天产生线索）会持续恶化。
2. dashboard 接口 findMany 无 select，把所有项目的大文本字段（financialData/aiCardJson 等）全部拉回只为数几个数。

同时用户要求重设计统计分析页的行业图谱（嫌气泡图丑）并增加时间维度切换。

**用户已确认的方向**：ECharts 矩形树图；时间口径用滚动窗口；分页改造范围"全部彻底改"（4 个列表 + workbench + dashboard 瘦身）。

## 核心事实（已核实）

- `canViewProject`（[permissions.ts#L25-L42](file:///Users/leeson/Desktop/投资管理系统/Investrask/I/src/lib/permissions.ts)）：特权角色全可见；INITIAL_TALK 公开；6 个受限阶段**仅认 members 不认 createdById**；其余值（REJECTED）兜底放行。`RESTRICTED_STAGES`/`PUBLIC_STAGES` 目前未导出。
- 现有 /api/projects 的 where 与 canViewProject **三处不等价**（缺 INITIAL_TALK、缺 REJECTED、createdById 分支过宽）——现状靠查后内存过滤兜底。服务端分页必须先做 where 等价化。
- 项目无任何图表库；Pagination 组件（props: currentPage/totalPages/onPageChange/total/pageSize）可直接复用。
- `passedStages` 是 JSON 数组字符串，各阶段值互不为子串，DB 级筛选可用 `contains: '"PRE_DD"'`。
- 前端缓存：`fetchWithCache`（30s TTL）、`invalidateCache` 支持 `projects:*`/`workbench:*` 通配（6 处调用），新缓存 key 必须保持前缀。
- Prisma `contains` 在 PostgreSQL 大小写敏感，前端现状是 toLowerCase 匹配，keyword 下推必须加 `mode: 'insensitive'`。

## 第一部分：服务端分页

### 1.1 新增共享模块 `src/lib/project-where.ts`

`permissions.ts` 导出名单常量（值不变）+ 新增 `OPEN_VIEW_STAGES = ['INITIAL_TALK', 'REJECTED']`。

```
buildProjectVisibilityWhere(user): Prisma.ProjectWhereInput
  // 特权角色 → {}；其余 → OR: [{ followStage: { in: OPEN_VIEW_STAGES } }, { members: { some: { userId } } }]
buildProjectScopeWhere(user, scope): Prisma.ProjectWhereInput
  // scope=mine：特权 → OR[createdById, members]；其余 → OR[members, AND[createdById, followStage in OPEN_VIEW]]
buildProjectListWhere(user, scope, { keyword?, stage?, industry?, year?, managerId? })
```

筛选下推写法：
- keyword → `OR: [{ name: { contains, mode:'insensitive' } }, { companyFullName: { contains, mode:'insensitive' } }]`
- stage → `passedStages: { contains: '"PRE_DD"' }`（累计口径，与前端 getPassedStages 一致）
- industry → 精确等值；year → `targetDate: { gte: new Date(year,0,1), lt: new Date(year+1,0,1) }`
- managerId → `OR: [{ createdById }, { members: { some: { userId } } }]`

**删除** /api/projects 里 L93-109 的 canViewProject 内存过滤（where 等价后保留会导致分页条数不齐）。
**行为修正声明**：受限角色（TEMP_VISITOR 等）将新增看到他人 INITIAL_TALK/REJECTED 项目——这是 canViewProject 本意，现状是被 where 缺陷掩盖的 bug。

### 1.2 接口契约

**`/api/projects` GET** 新参数：`page`（不传=全量，向后兼容）、`pageSize`（1-100，默认50）、`keyword`、`stage`、`industry`、`year`、`managerId`、`facets`（默认 `industries,years,stages`，workbench 传 `current`）。

响应：`{ projects, total, page, pageSize, scope, facets: { industries: string[], years: number[], stageCounts: Record<Stage,number>, currentStageCounts?: Record<Stage,number> } }`

- facets 用 1 次轻量查询（select: industry/targetDate/passedStages/followStage）内存计算；stageCounts 按 industry/year 联动（不随 keyword/stage，与现有卡片语义一致）；currentStageCounts 按 followStage 当前所处口径（workbench 卡片用）。

**`/api/project-leads` GET**：加 page/pageSize（不传 page=全量）；keyword 字段扩为 4 个（补 mainProducts）+ insensitive。响应 `{ leads, total, page, pageSize, scope }`。

**`/api/ai-leads` GET**：加 page/pageSize、`status`（all/released/locked/converted，released=已释放且非CONVERTED）；响应加 `stats: { total, released, locked, converted }`（权限 where 基础上计数）。

- `projects: Project[]` → `listData: { projects, total, facets }`；保留三套页码 state

- 删除前端 filter/slice（L401-466）、行业/年份派生（改从 facets 取）；阶段卡片改用 facets.stageCounts
- 列表缓存（projects:all/mine + subscribeCache）移除；可选保留 `projects:facets:${scope}` 缓存（保持前缀以兼容 invalidateCache 通配）

**`src/components/AILeadsTab.tsx`**：fetchLeads(page, debouncedSearch, filter) → filter 映射 status 参数；统计卡片从响应 stats 取；删除本地 filter/计数/slice。

**`src/app/workbench/page.tsx`**（两条请求替代全量分组）：
1. 卡片计数：`?scope=&facets=current&managerId=` → currentStageCounts 驱动阶段卡片
2. 分组列表：`?scope=&stage={selectedStage}&managerId=&page={stagePage}&pageSize=20`
- 删除本地 projects/projectsByStage/slice；缓存 key 改 `workbench:facets:${scope}:${managerId||'all'}`（保持 workbench: 前缀）
- managerId 语义从"仅创建者"扩为"创建者或成员"（维护口径，实施时注意）

**dashboard 瘦身**（`src/app/api/dashboard/route.ts`，响应结构不变、前端零改动）：两段查询——①轻量全量行（select: id/followStage/targetDate/stageChangedAt/createdById/createdBy.name）算卡片数和周新增 id 集；②仅周内子集拉明细（含 aiCardJson）。

## 第二部分：行业图谱重设计

### 2.1 ECharts 集成（`src/components/IndustryTreemap.tsx` 新建）

- `npm i echarts`；按需注册：`echarts/core` + `TreemapChart` + `TooltipComponent` + `CanvasRenderer`（约 110KB gzip，只进 /statistics chunk）
- `'use client'` 组件；statistics 页用 `dynamic(() => import('@/components/IndustryTreemap'), { ssr: false })`（statistics 页本身是客户端组件，合法）
- props: `{ industries: {industry, count}[], selected, onSelect }`
- treemap 配置：单层数据、`nodeClick: false`（自己接管选中）、`breadcrumb: false`、`roam: false`；label 显示行业名+数量；itemStyle 按 count 分 5 档渐变色阶（参考 news/page.tsx heatLevel 模式）+ 白色描边 gapWidth；选中项加粗描边高亮
- `chart.on('click')` → onSelect(toggle)；ResizeObserver → resize；dispose 清理
- **交互链路保留**：点击行业块 → selectedIndustry → 下方项目列表 +「⚡行业动态分析」按钮（handleAnalyzeIndustry 原样不动）

### 2.2 时间维度（滚动窗口）

**`/api/statistics/industry-map`** 加 `range` 参数（month/quarter/half/year，默认 year=现行为兼容）：
- month=now-30d、quarter=now-90d、half=now-180d、year=自然年（保留 year 参数浏览历史）
- 服务端 `resolveWindow(range, year)` → `targetDate: { gte: start, lt: end }`；顺带把该接口的全量拉取+内存过滤下推为 `buildProjectVisibilityWhere`
- 响应追加 `{ range, windowStart, windowEnd }`

**`src/app/statistics/page.tsx`**：
- 卡片右上角 4 档切换（近1月/近季度/近半年/当年）；仅 range=year 显示年份下拉；副标题显示窗口区间；切换时清空 selectedIndustry
- 删除气泡渲染（L184-202、L282-307），替换为 IndustryTreemap

## 风险清单
